# MPE Audio Asset Pipeline — SpeechGen Hebrew Provider

**Document:** `docs/specification/v1.1/MPE_AUDIO_ASSET_PIPELINE_SPEECHGEN_HEBREW_v0.1.md`  
**Status:** Reconciled draft (v0.1-r1) — Phase A decision record  
**Scope:** Design of the `mpe_audio` subsystem that prepares approved Hebrew speech assets for the MindTune Protocol Engine (MPE). This document is design only; it contains no production code and does not alter MPE v1.1 runtime contracts without a separate ADR.

This document was originally authored in a separate environment and has been reconciled with the actual MPE v1.1 repository state. A reconciliation change log is provided at the end.

## 1. Executive summary

MindTune teaches primarily through listening, internal speech, anticipation, recall, and confirmation, often with eyes closed. MPE assembles audio dynamically and may adapt pauses, playback rate, repetitions, and item progression during a session, using behavioral performance, response latency, item history, and EEG as optional context.

This design introduces `mpe_audio`, a separate package that turns Hebrew linguistic items into locally cached, validated, human-approved audio assets, generated by SpeechGen through the existing MPE `Renderer` boundary. The central claim is a hard separation between:

- **content** (what the linguistic truth is),
- **generation** (how a provider synthesizes speech),
- **approved assets** (immutable, versioned, auditable artifacts), and
- **runtime** (how MPE plays and adapts, using only local assets).

SpeechGen is never called synchronously inside the adaptive loop. Provider calls happen only during preparation, prefetch, or an explicit non-time-critical workflow. Every approved asset is reproducible and auditable, requires human linguistic approval, and is addressed by a stable `logical_audio_asset_id` and an immutable `audio_asset_version_id`. No provider URL or secret leaks into a protocol definition or MPE event.

**Recommendation:** `APPROVE_AUDIO_PIPELINE_IMPLEMENTATION_SCOPE`, conditioned on the open decisions in §23 and the external ADR actions noted in §20 being resolved before implementation.

## 2. Preservation of the original adaptive-audio concept

This subsystem preserves the original adaptive audio-protocol concept formerly referred to as "Mantra":

1. **Listening-first, eyes-closed capable.** All protocol steps are expressible without visual dependency.
2. **Internal speech, anticipation, recall, confirmation.** Covert operations are represented by instructions and silence, not by audio.
3. **Dynamic assembly by MPE.** MPE composes sequences at runtime from approved assets; it is not a linear playlist.
4. **Runtime adaptation.** Pause duration, playback rate within validated bounds, repetition count, item selection, difficulty progression, and recovery/consolidation transitions are runtime decisions.
5. **EEG is a contextual modulator only.** EEG may bias bounded adaptation through MPE `AdaptationDecision` events. It never scores answers, fabricates performance, overrides behavioral evidence, or makes irreversible learning-state changes without corroboration.
6. **SpeechGen generates speech, nothing else.** It is a stateless synthesis function behind the MPE `Renderer` interface.

## 3. System boundaries

Seven layers, each with a one-directional dependency toward "lower" layers. Nothing above the asset registry knows the provider exists.

```text
6. MPE runtime adaptation (pauses, playback rate, repetition, selection,
   progression, EEG-as-context via AdaptationDecision / ScheduleDecision)
7. MPE session event recording (audio_asset_version_id, playback params, reasons)
   ─────────────────────────────────────────────────────────────────────────────
5. MPE typed protocol model (Instruction, StimulusRequest, ResponseWindow,
   ScheduleDecision, AdaptationDecision, FeedbackEvent)
   ─────────────────────────────────────────────────────────────────────────────
4. mpe_audio asset registry (logical_audio_asset_id → approved audio_asset_version_id)
   ─────────────────────────────────────────────────────────────────────────────
3. mpe_audio asset pipeline (request build → synth → download → hash → normalize
   → validate → approve → store → version → regeneration policy)
   ─────────────────────────────────────────────────────────────────────────────
2. mpe_audio TTS provider adapter (SpeechGen adapter implementing MPE Renderer Protocol)
   ─────────────────────────────────────────────────────────────────────────────
1. Hebrew linguistic content layer (ContentItem from HebrewDomainProvider,
    surface_form, normalized_form, pronunciation_metadata)
```

Boundary rules:

- Layer 1 is the authoritative source of vocalization and morphology. The TTS provider is never authoritative for reading/vocalization.
- Provider response dictionaries (raw JSON) exist only inside Layer 2. They are converted to typed results at the adapter edge and never propagate upward.
- Protocol definitions (Layer 5) reference only `logical_audio_asset_id` and `voice_profile_id`, never provider URLs, voice names, or synthesis params.
- Layers 6–7 operate exclusively on already-approved local assets.

## 4. End-to-end data flow

Two disjoint phases: preparation (may call SpeechGen) and runtime (never calls SpeechGen).

### Preparation phase (offline / pre-session / prefetch)

```text
ContentItem (HebrewDomainProvider)
   │
   ▼
Build canonical SynthesisRequest  ── request fingerprint (idempotency)
   │
   ├─ registry hit on fingerprint? ── yes ─▶ reuse existing audio_asset_version_id
   │
   no
   ▼
Cost/quota preflight (balance check, budget ceiling, dry-run gate, explicit confirm)
   ▼
Renderer.render(request) via adapter ──▶ Immediate | Pending(job) | Failure
   ▼  (poll get_job if Pending)
Download provider file (safe limits, MIME/TLS checks, atomic temp)
   ▼
Integrity hash (audio bytes) + content hash (normalized input text)
   ▼
Normalize (loudness, trim, channel/sample-rate policy) → master + delivery
   ▼
Extract metadata (format, sample_rate, channels, duration)
   ▼
Automated validation (format/rate/duration/hash/silence checks)
   ▼
Human linguistic review ──▶ approved | rejected | superseded later
   ▼
Persist AudioAssetVersion + manifest (atomic finalize)
   ▼
Register logical_audio_asset_id → approved audio_asset_version_id(s)
```

### Runtime phase (online / in-session — SpeechGen NEVER called)

```text
Protocol Instruction or StimulusRequest references logical_audio_asset_id
   │
   ▼
mpe_audio registry deterministic lookup ──▶ approved audio_asset_version_id
   │
   ▼
MPE runtime decisions: runtime_playback_rate (bounded), pause, repetition
   │          ▲
   │          └── inputs: behavioral evidence, latency, item history, EEG context
   ▼
Play local delivery asset
   ▼
Emit stimulus_started / stimulus_completed / feedback_started (audio_asset_version_id recorded)
```

If a required asset is missing at runtime, do not synthesize inline. Fall back to another approved voice/role variant if available; otherwise skip/degrade the step and emit a `safety_rule_triggered` or `recovery_inserted` event.

## 5. Provider-neutral architecture

`mpe_audio` implements the MPE `Renderer` Protocol defined in `MPE_PROVIDER_BOUNDARIES.md` and `packages/mpe/src/mpe/providers.py`:

```python
class Renderer(Protocol):
    def capabilities(self) -> dict[str, Any]: ...
    def render(self, request: dict[str, Any]) -> dict[str, Any]: ...
```

The adapter-side interface is internal to `mpe_audio`:

```text
interface SpeechSynthesisProvider:
    list_voices(filter: VoiceFilter) -> list[ProviderVoice]
    synthesize(req: ProviderSynthesisRequest) -> SynthesisOutcome
    get_job(job_ref: ProviderJobRef) -> SynthesisOutcome
    get_balance() -> Balance
    delete_remote_job(job_ref: ProviderJobRef) -> None   # optional best-effort cleanup
```

Explicit result types:

```text
SynthesisOutcome =
    | ImmediateResult(audio_url, provider_job_id, duration_s, cost, balance_after,
                      format, sample_rate?, channels?, raw_meta_ref)
    | PendingJob(job_ref, parts, parts_done, estimated_cost)
    | ProviderFailure(kind: ProviderErrorKind, message_redacted, retryable: bool,
                      http_status?, provider_code?)
```

Design constraints:

- Do not force asynchronous semantics onto all providers. SpeechGen `/text` is synchronous → `ImmediateResult`; `/longtext` is async → `PendingJob` resolved via `get_job`.
- Use explicit result types, not exceptions-for-control-flow and not raw dicts.
- Provider dictionaries never leak above the adapter.
- `ProviderErrorKind` is a provider-neutral enum: `auth`, `insufficient_balance`, `voice_unavailable`, `rate_limited`, `transient_network`, `timeout`, `malformed_response`, `missing_file`, `provider_internal`.

## 6. SpeechGen adapter design

Based on the official SpeechGen API as reviewed in the original Cloud design.

Endpoints used:

| Purpose | Endpoint | Method | Notes |
|---|---|---|---|
| Instant synthesis | `/text` | POST/GET | ≤ 2,000 chars, returns file immediately. |
| Long-text synthesis | `/longtext` | POST/GET | ≤ 1,000,000 chars, returns task id, poll `/result`. |
| Subtitle synthesis | `/subs` | POST/GET | Not needed for MindTune v0.1. |
| Poll result | `/result` | POST/GET | For `/longtext` and `/subs`. |
| Voice discovery | `/voices` | GET | Optional `&langs=he` filter. |
| Balance | `/balance` | POST/GET | Params `token`, `email`. |
| Delete project | `/delete` | POST/GET | Params `token`, `email`, `id`. Remote cleanup only. |

### Authentication

Every request requires `token` (secret API key) and `email` (account email). Both are loaded from environment variables / secret store; never in source, manifests, or logs. Use POST form-urlencoded; never place credentials in a GET query string.

### Request parameters used

`voice`, `text`, `speed` (0.1–2.0), `pitch` (−20..20), `style` + `styledegree`, `role`, `pause_sentence`/`pause_paragraph` (ms), `volume` (10–200), `format` (`mp3|wav|ogg|opus|flac`), `sample_rate` (Hz), `bitrate` (kbps, lossy only), `channels` (1|2). Background-music params are disallowed for training assets.

### Response fields → typed mapping

Provider JSON (`id`, `status` 1/0/-1, `file`, `file_cors`, `parts`, `parts_done`, `duration`, `format`, `error`, `balans`, `cost`) is parsed into `SynthesisOutcome`. Numeric provider status codes are mapped to `ProviderJobState` (`ready`, `processing`, `error`) so no provider codes leak upward.

### Retry behavior

- Idempotent retries only on `transient_network`, `timeout`, `rate_limited`.
- Never blind-retry a `/text` call that may have already been billed; first check the request fingerprint.
- Exponential backoff with jitter, capped attempts, hard per-attempt timeout.
- `/longtext` polling is a preparation-phase activity only.

### Provider identifiers persisted

`provider = "speechgen"`, `provider_voice_id`, `provider_project_id`, and `provider_job_ref` are stored on the `AudioAssetVersion` manifest for audit but are not used for runtime lookup.

### Cost reporting

Each synthesis records `cost` and `balans` in the asset manifest and batch report.

### Choosing `/text` vs `/longtext`

MindTune items are short, so `/text` is the default. `/longtext` is retained for future immersion passages and bulk narration.

## 7. Linguistic source model

Layer 1 is authoritative. The provider must not become the source of vocalization or morphology.

```text
type LinguisticAudioSource:
    linguistic_item_id: str               # ContentItem.content_item_id
    language: str = "he"
    locale: str = "he-IL"
    text_canonical: str                   # ContentItem.surface_form
    text_niqqud: str                      # pointed synthesis input
    text_unpointed: str                  # display / connected-speech form
    expected_reading: ExpectedReading   # structured, see §B
    context_sentence: Optional[str]
    lemma: str
    root: Optional[str]
    morphology: Morphology
    translation: dict[str, str]
    semantic_tags: list[str]
    grammatical_tags: list[str]
    notes: Optional[str]
```

Rules:

- Isolated/ambiguous items are synthesized from `text_niqqud`.
- Connected-speech assets may use `text_unpointed` with a `context_sentence`.
- `expected_reading` is the human-authored ground truth. If the provider pronunciation disagrees, the asset is rejected; the source is never rewritten.
- The normalized input text sent to the provider is captured on the asset (`normalized_input_text`) and hashed (`content_hash`) for reproducibility.

## 8. Voice profiles

Curriculum records must not bind to a raw provider voice name. A versioned internal `VoiceProfile` provides indirection.

```text
type VoiceProfile:
    voice_profile_id: str               # e.g. "hebrew.primary_female.v1"
    display_name: str
    language: str = "he"
    provider: str                       # "speechgen"
    provider_voice_id: str             # resolved provider voice name
    approved_synthesis_params: SynthParams
    allowed_asset_roles: set[AssetRole]
    allowed_runtime_playback_rate_bounds: {min, max, evidence_grade, pilot_status}
    review_status: ReviewStatus
    created_at, approved_at, approved_by
    notes: Optional[str]
```

This lets the system replace a provider voice without rewriting curriculum: bump to `hebrew.primary_female.v2`, regenerate and re-review assets, and repoint the registry. The `ProtocolVersion` keeps referencing the logical profile family.

## 9. Asset lifecycle

States:

```text
generated ─▶ pending_review ─▶ approved ─▶ (superseded)
                     └────────▶ rejected
```

- `generated` — synthesized, downloaded, normalized, auto-validated. Not usable for training.
- `pending_review` — queued for human linguistic review.
- `approved` — passed review; immutable; runtime-eligible; registered.
- `rejected` — failed review; retained for audit; may trigger regeneration.
- `superseded` — previously approved, replaced by a newer approved version; retained for replay.

### Immutability and versioning

Approved assets are immutable. Any change (provider voice, params, normalization policy, source text) produces a new `audio_asset_version_id` with a `parent_asset_version_id` link. Historical events always resolve to the exact version played.

### Regeneration policy

Regeneration is triggered by: review rejection; provider pronunciation change detected on re-validation; voice profile version bump; normalization policy change; corrupt/lost local asset. Regeneration always re-enters at `generated` and must be re-reviewed before `approved`. Fingerprint dedup avoids needless paid calls when nothing material changed.

## 10. Storage and formats

### Directory layout

```text
<MPE_AUDIO_STORE_ROOT>/
  objects/
    <audio_hash[:2]>/<audio_hash>.flac
    <audio_hash[:2]>/<audio_hash>.opus
    <audio_hash[:2]>/<audio_hash>.mp3
  assets/
    <logical_audio_asset_id>/
      <audio_asset_version_id>/
        asset.json
        source.txt
        provider_raw.json   # redacted
        review.json
```

### Master vs delivery format

- **Archival master:** FLAC (lossless). If SpeechGen returns lossy for a given voice, store the highest-quality available as master and record `master_is_lossy=true`.
- **Delivery primary:** Opus.
- **Compatibility fallback/export:** MP3.
- **Mono** for all pedagogical speech.
- **Sample rate:** 48 kHz master; delivery derived from master.
- **Loudness normalization:** target is a provisional `-16 LUFS` mono with a `-1.5 dBTP` true-peak ceiling. The value is recorded with `evidence_grade: simulation_default` and is final only after pilot validation.
- **Silence trimming:** trim leading/trailing silence to a fixed small pad (e.g. 150 ms) so MPE controls anticipation/recall pauses. Never trim internal silence.
- **File naming:** fixed names in the version directory (`master.flac`, `delivery.opus`, `fallback.mp3`).
- **Checksums:** `audio_hash` over master bytes; `content_hash` over normalized input text.
- **Atomic writes:** download to a temp file on the same filesystem, fsync, then rename into the final version directory. No consumer sees a partial asset.
- **Deduplication:** keyed on the request fingerprint (no paid re-synthesis) and on `audio_hash` (store once, reference many). Logical records are never merged.

## 11. Protocol model integration (replaces textual DSL)

The MPE v1.1 typed model is used instead of a textual DSL. Audio steps are expressed with the existing objects:

| Original DSL primitive | MPE v1.1 equivalent | Notes |
|---|---|---|
| `play(asset_ref, role, voice_profile)` | `Instruction` with `instruction_type = PRESENT_STIMULUS` + `StimulusRequest` | `asset_ref` is a `logical_audio_asset_id` resolved at runtime. |
| `anticipate(duration_policy)` | `Instruction` with `instruction_type = INSTRUCT_COVERT_RETRIEVAL` or `WAIT_DURATION` + `ResponseWindow` | Silence window is a runtime timing decision. |
| `pause(duration_policy)` | `WAIT_DURATION` instruction or `ResponseWindow` pause | Runtime timing decision. |
| `expect(response_spec)` | `REQUEST_OVERT_RESPONSE` instruction + `ResponseWindow` | Behavioral observation. |
| `confirm(asset_ref)` | `FeedbackEvent` with `feedback_category = KNOWLEDGE` and a `StimulusRequest` | Uses approved asset. |
| `repeat(count_policy, target)` | `ScheduleDecision` or `AdaptationDecision` | Runtime repetition decision. |
| `branch(condition, then, else)` | `ScheduleDecision` or `safety_rule_triggered` | Protocol transition. |
| `transition(target_state)` | `ScheduleDecision` (`decision_type` = `next_block`, `session_end`, `insert_review`, `offer_break`) | Protocol transition. |

No provider-specific field appears anywhere in `ProtocolVersion`, `ProgramVersion`, `Block`, `Trial`, `Instruction`, or `StimulusRequest`.

## 12. Runtime adaptation and EEG policy

### Adaptation levers (runtime only, from local assets)

- `pause_duration` — within a per-step bounded range.
- `playback_rate` — within `VoiceProfile.allowed_runtime_playback_rate_bounds`.
- `repetition_count` — bounded.
- `item_selection` — from approved items.
- `difficulty_progression` — bounded steps.
- `recovery/consolidation transitions` — `ScheduleDecision`.

### Synthesis speed, delivery style, and runtime playback rate

Three distinct concepts:

- `synthesis_speed` — SpeechGen `speed` parameter at generation time; part of the asset version fingerprint.
- `canonical_delivery_style` — intended baseline delivery of an asset role (e.g. `natural` vs `pedagogical_slow`), fixed at generation and reviewed.
- `runtime_playback_rate` — rate multiplier applied by the MPE player at runtime.

Do not time-stretch outside validated bounds. If a slower rate is needed, select or generate a separate `pedagogical_slow` `AudioAssetVersion`.

### EEG policy

EEG may influence `AdaptationDecision` events for pause, repetition, or difficulty hold. EEG must not mark a linguistic answer correct/incorrect, invent user performance, override behavioral evidence, or make irreversible learning-state changes. Every EEG-influenced adaptation emits a reasoned `AdaptationDecision` with `eeg_context_ref` and `eeg_influenced: true`.

## 13. Event and replay model

Audio-specific data is carried as extensions to existing MPE events, not as new event types.

### `stimulus_ready` / `stimulus_started` / `stimulus_completed` payload extensions

```text
{
  "stimulus_request_id": "...",
  "rendered_stimulus_id": "...",
  "renderer_version": "...",
  "duration": 1.23,
  "rendered_at": 12.34,
  "audio_asset_version_id": "...",   # concrete version played
  "voice_profile_id": "...",
  "asset_role": "...",
  "delivery_format": "opus"
}
```

### `feedback_started` payload extensions

```text
{
  "feedback_event_id": "...",
  "trial_id": "...",
  "feedback_category": "KNOWLEDGE",
  "feedback_type": "correct_answer",
  "content_item_id": "...",
  "audio_asset_version_id": "...",
  "voice_profile_id": "...",
  "runtime_playback_rate": 1.0,
  "started_at": 12.34
}
```

### `AdaptationDecision` / `adaptation_proposed` extensions

Audio-related target dimensions may include `pause_duration`, `playback_rate`, `repetition_count`. The decision records `previous_value`, `new_value`, `allowed_bounds`, `reason`, `policy_rule_id`, and optional `eeg_context_ref`.

### Replay guarantee

Given the event stream and the immutable asset store, the exact `audio_asset_version_id` and playback parameters are recoverable. Because assets are immutable and events store `audio_asset_version_id`, supersession never breaks historical replay. New sessions may resolve a `logical_audio_asset_id` to the then-current approved version, but replay uses the recorded version.

## 14. Security

- Credentials from environment / secret store only (`SPEECHGEN_TOKEN`, `SPEECHGEN_EMAIL`).
- No credentials in source control, manifests, logs, or MPE events.
- Log redaction of `token`/`email` in all logs and `provider_raw.json`.
- Every HTTP call has a hard timeout; polling has an overall deadline.
- TLS verification always enabled.
- Safe download limits: max content length, max duration.
- MIME and audio header validation; reject mismatches.
- Allow only HTTPS redirects to the expected SpeechGen host; reject cross-host or downgrade redirects.
- Atomic finalization; clean up temp files on any failure path.
- Remote cleanup is optional and best-effort.

## 15. Cost and quota controls

- Preflight balance check via `/balance` before any batch.
- Estimated request cost per item and batch total shown before generation.
- Per-batch budget ceiling and maximum item count; abort if projected cost exceeds the ceiling.
- Dry-run mode builds every request and reports estimated cost and cache hits/misses, making zero paid calls.
- Explicit confirmation required before any paid generation.
- Cost recorded per asset and batch report.
- Stop-on-low-balance when `balans` falls below a configured floor.
- Retry policy avoids duplicate billing through fingerprint dedup.

## 16. Pilot corpus design

Do not mass-generate before the pilot is approved.

Coverage (50–100 representative Hebrew items):

- Isolated nouns; verbs across several binyanim (`pa'al`, `pi'el`, `hif'il`, `hitpa'el`, ...).
- Masculine/feminine, singular/plural.
- Present/past/future; construct state.
- Gutturals, reduced vowels, sheva.
- Stress-sensitive words, unpointed ambiguities, minimal pairs.
- Short natural sentences, morphology sequences, root families.

Generate each item with multiple candidate voices (2–3 Hebrew voice profiles). Human reviewers score on pronunciation, stress, vowel realization, consonant quality, naturalness, consistency, suitability for isolated/connected speech, and suitability at altered playback rates. The output is a per-voice score matrix, selection of primary voice profile(s), and empirically validated runtime playback-rate bounds. Only after pilot approval does bulk generation proceed.

## 17. Review workflow

Human linguistic approval is mandatory before `approved`.

1. Batch generates assets → `generated` → auto-validation → `pending_review`.
2. Reviewer package export: audio (natural + slow variants), `text_niqqud`, `text_unpointed`, expected reading, translation, rubric.
3. Reviewer listens with the intended eyes-closed/isolated framing and scores; decision `approved` or `rejected` with `reviewer_notes`.
4. `approved` → immutable + registered. `rejected` → retained; may trigger regeneration.
5. A new approved version supersedes the prior; historical events still replay the old version.

```text
type AudioAssetReview:
    review_id: str
    audio_asset_version_id: str
    reviewer_id: str
    reviewed_at: timestamp
    decision: {approved, rejected}
    scores: RubricScores
    reviewer_notes: str
    expected_reading_match: bool
```

## 18. Failure modes

| Failure | Handling |
|---|---|
| Invalid token | `ProviderFailure(auth)`; abort batch; redact in logs; never retry blindly. |
| Insufficient balance | `ProviderFailure(insufficient_balance)`; stop; report. |
| Voice removed by provider | Voice profile validation fails; block generation for that profile; update + re-review. |
| Provider changes pronunciation | Detected on re-validation; flag for regeneration + re-review; never auto-approve. |
| Transient network failure | Retry with backoff; fingerprint dedup first. |
| Timeout | Bounded per-call + overall deadline; retry if within policy. |
| Duplicate request | Fingerprint dedup returns existing asset/job; no new billing. |
| Malformed JSON | `ProviderFailure(malformed_response)`; no partial persist. |
| Provider success but missing file | `ProviderFailure(missing_file)`; treat as failure; cleanup. |
| Corrupt/truncated audio | Fails MIME/header/duration/hash validation; discard temp. |
| Unexpected format | Format-match validation fails; reject. |
| Wrong sample rate | Metadata validation fails; reject/regenerate. |
| Hash mismatch on load | Refuse to serve; mark asset compromised; regenerate. |
| Review rejection | State `rejected`; retained; optional regeneration. |
| Asset deleted remotely | Irrelevant; local copy is authoritative. |
| Local disk full | Atomic write fails cleanly; alert; no partial asset. |
| Interrupted atomic write | Temp discarded; final dir never partial. |
| Unavailable asset during session | No inline synthesis. Fall back to another approved variant or skip/degrade + emit failure event. |
| Protocol requires an ungenerated asset | Preparation validation catches this pre-session; runtime degrades gracefully + logs. |

## 19. Test strategy

- Provider adapter unit tests with mocked HTTP.
- Response parsing tests (1/0/-1 → typed outcomes; field extraction; `balans`/`cost`).
- Request fingerprint tests (identical inputs → identical fingerprint; material param change → different fingerprint).
- Manifest validation tests (schema, required fields, no secrets).
- File integrity tests (audio/content hash round-trip; corrupt detection; format/sample-rate/duration checks).
- No-secret logging tests.
- Atomic download tests.
- Cost guard tests.
- Cache hit/miss tests.
- Provider-independent contract tests (a second mock provider satisfies the `Renderer` Protocol).
- Protocol asset-resolution tests (DSL-style logical reference → deterministic `audio_asset_version_id`; no provider fields in protocol fixtures).
- Runtime test proving the adaptive loop makes zero SpeechGen calls.
- Replay tests (exact asset version + playback params recoverable after supersession).

## 20. Packaging options

The production subsystem is `packages/mpe_audio/`. It must not be folded into `packages/mpe`. A `tools/` location is acceptable only as a temporary lift-and-shift staging area during early prototyping.

```text
packages/mpe/            # no audio deps
packages/mpe_audio/      # SpeechGen adapter, pipeline, registry, CLI, optional audio deps
```

`packages/mpe` depends on `packages/mpe_audio` only by configuration (`renderer_id` string / entry point). `packages/mpe_audio` depends on `packages/mpe` for the `Renderer` Protocol, event envelope, and identifier/types. There is no circular import.

## 21. Proposed CLI

```text
mpe-audio voices list [--lang he]          # /voices discovery
mpe-audio pilot prepare                     # build pilot manifest (multi-voice)
mpe-audio generate --manifest <path> [--dry-run] [--budget N] [--max-items N] [--confirm]
mpe-audio review export [--batch <id>]      # reviewer package
mpe-audio approve <logical_audio_asset_id>@<version>
mpe-audio validate [--all | --asset <id>]   # integrity/format/hash checks
mpe-audio cost-report [--batch <id>]        # per-asset + total cost
```

`generate` enforces cost controls. `mpe-audio` is a separate console script from `mpe` to avoid namespace collision and to keep audio dependencies out of the core runtime.

## 22. Implementation phases (reconciled)

1. **Phase A — Contracts & interface.** Define shared contract types, `Renderer` implementation, and data models. Resolve open decisions. No paid calls. (This document.)
2. **Phase B — SpeechGen adapter.** Implement adapter behind the `Renderer` Protocol with mocked-HTTP unit tests.
3. **Phase C — Pipeline & storage.** Request build/fingerprint, safe download, hashing, normalization (FLAC master / Opus delivery), atomic writes, dedup, manifest.
4. **Phase D — Registry & `Renderer` resolution.** `logical_audio_asset_id` → `audio_asset_version_id` registry, deterministic resolution, integration with `StimulusRequest`/`RenderedStimulus`.
5. **Phase E — Cost/quota + CLI.** Preflight, dry-run, budget ceilings, batch report, `mpe-audio` CLI.
6. **Phase F — Pilot.** Generate 50–100 items across multiple voices; run rubric; validate playback-rate bounds; approve primary voice profile(s). Gate before bulk.
7. **Phase G — Runtime integration.** Event/replay model, adaptive-loop uses only local assets, no-provider-call test.
8. **Phase H — ADR updates.** Update `MPE_OPEN_DECISIONS.md` #7 and `MPE_HEBREW_PROVIDER_CONTRACT.md` to add `speechgen` as a candidate `renderer_id`, if the pilot selects it.

## 23. Risks and open decisions

Risks:

- Hebrew TTS quality on hard cases is unproven for SpeechGen → mitigated by pilot gate + mandatory review.
- Provider drift (voice removed, pronunciation changed) → voice-profile versioning, re-validation, local-copy independence.
- Playback-rate phonetic degradation → conservative bounds + separately synthesized slow variants.
- Duplicate billing on retries → fingerprint dedup + cost guards.
- Master fidelity if a voice only outputs lossy → `master_is_lossy` flag + review.

Open decisions to resolve in Phase A/F:

1. Delivery codec fallback: is Opus universally decodable, or is MP3 the safer default delivery? → pilot.
2. Loudness target (`-16 LUFS` mono) and playback-rate bounds → finalize empirically from pilot.
3. Content-addressed dedup store for shared binary objects → include in v0.1 (recommended) or defer.
4. `expected_reading` conventions → finalize IPA/transliteration scheme in pilot.
5. Remote `/delete` policy → `auto_delete_remote=False` default; may be enabled later.
6. ADR to add `speechgen` as a candidate `renderer_id` in MPE v1.1 documents.
7. ADR to extend `stimulus_started`/`feedback_started` payloads with `audio_asset_version_id`.

## 24. Acceptance criteria

1. Protocol fixtures reference only `logical_audio_asset_id` + `voice_profile_id` + `asset_role`; no provider URLs, voice names, or synthesis params. (Test.)
2. A simulated adaptive session makes zero SpeechGen calls. (Test.)
3. `synthesis_speed`, `canonical_delivery_style`, and `runtime_playback_rate` are distinct and separately recorded; runtime rate stays within validated bounds or a pedagogical variant is used. (Test.)
4. Niqqud is the canonical synthesis input for isolated/ambiguous items; the provider is never the authoritative vocalization source. (Test.)
5. No asset reaches `approved` without a recorded `AudioAssetReview`.
6. Every approved asset stores full metadata and is reproducible; audio/content hashes verify on load. (Test.)
7. Credentials come only from env/secret store; no secret appears in logs, events, or manifests; TLS verification enabled. (Tests.)
8. Cost controls: dry-run makes no paid calls; budget ceiling + max item count enforced; per-asset and batch cost recorded; stop-on-low-balance works; retries never double-bill. (Tests.)
9. The pilot is completed and approved before any bulk generation.
10. Given the event stream + immutable asset store, the exact `audio_asset_version_id` and playback parameters are recoverable, including after supersession. (Test.)
11. EEG never scores answers or overrides behavioral evidence; every EEG-influenced adaptation emits a reasoned bounded `AdaptationDecision`.
12. Provider response dictionaries never leak above the adapter; a second mock provider satisfies the `Renderer` Protocol. (Test.)

## 25. Final recommendation

The reconciled design cleanly separates linguistic truth, provider generation, approved immutable `AudioAssetVersion`s, and runtime `RenderedStimulus`. It keeps SpeechGen out of the adaptive loop, preserves the Mantra cognitive model, mandates human approval, enforces security and cost control, and gates bulk generation behind a multi-voice pilot.

**Recommendation:** `APPROVE_AUDIO_PIPELINE_IMPLEMENTATION_SCOPE`, subject to:

- acceptance of this reconciled document and `MPE_AUDIO_PIPELINE_PHASE_A_DECISION_RECORD.md`;
- completion of the ADR actions in §23 (adding `speechgen` as a candidate `renderer_id` and extending event payloads);
- pilot validation of the empirical parameters in §23;
- explicit user authorization before any implementation work begins.
